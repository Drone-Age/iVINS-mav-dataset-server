# Політика безпеки

[English version](SECURITY.md)

## Підтримуваний реліз

Виправлення безпеки отримує лише найновіший реліз `4.x`.

## Межа TLS-розгортання

У Docker Distribution 2.1.0 Backend працює через HTTP лише у приватній
Compose-мережі без host-порту. Зафіксований Caddy відкриває 80/443, автоматично
керує сертифікатом, перенаправляє HTTP на HTTPS і додає HSTS. Access log Caddy
вимкнений, щоб bearer-ключі, query-параметри квитків і приватні шляхи не
потрапляли до журналу. Перед використанням ключа виконайте `verify-tls.ps1`.

Окремий e2e `user`-ключ зберігайте лише як `DSM_SERVER_TOKEN`. Після переходу
на HTTPS відкличте всі ключі, які могли пройти через старий HTTP endpoint.

## Межа HTTP-застосунку

Застосунок свідомо працює через HTTP. HTTP не забезпечує конфіденційність або
цілісність транспорту. У будь-якій недовіреній мережі оператор повинен
завершувати TLS на reverse proxy/маршрутизаторі або застосовувати довірену VPN.
За можливості Backend має слухати лише адресу proxy або localhost.

API-ключі є bearer credentials. Кожен, хто перехопив ключ, може користуватися
ним до відкликання. Ніколи не розміщуйте ключі в URL, файлах репозиторію,
змінних Compose, журналах, повідомленнях або публічному виводі CI.

Публічна сторінка `/` та `/admin` не зберігають введений ключ у сховищі
браузера. Вони тримають його в пам'яті сторінки й передають у заголовку
Authorization лише до same-origin API. Гості можуть переходити тільки до
зовнішніх дзеркал; локальні артефакти потребують ключа `user` або `admin`.
Браузерні завантаження використовують одноразовий 60-секундний квиток, відкритий
текст якого сервер не зберігає.

Без TLS ці засоби не захищають ключ або квиток від мережевого перехоплення.
Публічний доступ дозволяється лише після успішного `verify-tls.ps1`.

## Контрольний список оператора

- Створіть перший admin-ключ через `api_keys.py` на сервері; наступні ключі
  створюйте лише через CLI або автентифікований інтерфейс адміністратора.
- Використовуйте ключі `user` для споживачів; `admin` — лише для операторів і
  видавців.
- Під час ротації майте щонайменше два окремо позначені admin-ключі.
- Негайно відкликайте замінені або підозрілі ключі.
- Обмежте доступ до `.env` і повного дерева `var/`.
- Резервуйте повне дерево `var/` як одне ціле та перевіряйте відновлення.
- Оновлюйте Docker Desktop, ОС хоста й container image.
- Зберігайте та контролюйте audit logs контейнера щодо помилок автентифікації,
  rate limits і неочікуваних write-запитів.
- Не додавайте host-порт для Backend service.

додавайте до issue API-ключі, приватні метадані Dataset або вміст артефактів.
